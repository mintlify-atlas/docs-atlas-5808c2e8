## Overview

OpenCBS Cloud uses JWT (JSON Web Token) based authentication. All API requests (except public endpoints) must include a valid Bearer token in the `Authorization` header.

## Authentication Flow

1. **Login** - Send credentials to obtain a JWT token
2. **Store Token** - Save the token securely on the client
3. **Authenticate Requests** - Include the token in the `Authorization` header
4. **Session Management** - Token is validated on each request
5. **Logout** - Invalidate the session when done

## Login

### Endpoint

```
POST /api/login
```

Authenticate a user and receive a JWT token for subsequent API requests.

### Request Body

<ParamField body="username" type="string" required>
  User's username or email address
</ParamField>

<ParamField body="password" type="string" required>
  User's password
</ParamField>

### Response

<ResponseField name="data" type="string">
  JWT token to use for authenticated requests
</ResponseField>

### Example Request

<CodeGroup>
```bash cURL
curl -X POST \
  https://your-instance.opencbs.cloud/api/login \
  -H 'Content-Type: application/json' \
  -d '{
    "username": "admin",
    "password": "your-password"
  }'
```

```javascript JavaScript
const response = await fetch('https://your-instance.opencbs.cloud/api/login', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    username: 'admin',
    password: 'your-password'
  })
});

const { data: token } = await response.json();
```

```python Python
import requests

response = requests.post(
    'https://your-instance.opencbs.cloud/api/login',
    json={
        'username': 'admin',
        'password': 'your-password'
    }
)

token = response.json()['data']
```
</CodeGroup>

### Example Response

```json
{
  "data": "eyJhbGciOiJIUzUxMiJ9.eyJzdWIiOiJhZG1pbiIsImlzcyI6ImNvbS5vcGVuY2JzLmNvcmUifQ.xyz..."
}
```

### Error Response

```json
{
  "httpStatus": 401,
  "errorCode": "invalid_credentials",
  "message": "Invalid username or password."
}
```

## Using the Token

Once you have a token, include it in the `Authorization` header for all API requests:

```
Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...
```

### Example Authenticated Request

<CodeGroup>
```bash cURL
curl -X GET \
  https://your-instance.opencbs.cloud/api/currencies \
  -H 'Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...' \
  -H 'Content-Type: application/json'
```

```javascript JavaScript
const response = await fetch('https://your-instance.opencbs.cloud/api/currencies', {
  method: 'GET',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  }
});
```

```python Python
headers = {
    'Authorization': f'Bearer {token}',
    'Content-Type': 'application/json'
}

response = requests.get(
    'https://your-instance.opencbs.cloud/api/currencies',
    headers=headers
)
```
</CodeGroup>

## Token Details

### Token Structure

The JWT token is signed using the **HS512** (HMAC-SHA512) algorithm and contains:

- **Subject (`sub`)**: Username of the authenticated user
- **Issuer (`iss`)**: `com.opencbs.core`
- **Signature**: HMAC-SHA512 signature for verification

<Note>
The token does not have a built-in expiration time. Session validity is managed server-side through user session tracking.
</Note>

### Token Format

```
eyJhbGciOiJIUzUxMiJ9.eyJzdWIiOiJhZG1pbiIsImlzcyI6ImNvbS5vcGVuY2JzLmNvcmUifQ.signature
```

Parts:
1. **Header**: `{"alg":"HS512"}`
2. **Payload**: `{"sub":"admin","iss":"com.opencbs.core"}`
3. **Signature**: HMAC-SHA512 signature

## Session Management

### Session Validation

On each authenticated request, the server:

1. Extracts the token from the `Authorization` header
2. Verifies the token signature
3. Validates the username from the token
4. Checks if the user is active (status = `ACTIVE`)
5. Verifies the session hasn't expired
6. Updates the user's last activity time

### Session Expiration

Session timeout is controlled by the system setting `EXPIRATION_SESSION_TIME_IN_MINUTES`:

- **Value > 0**: Session expires after N minutes of inactivity
- **Value = 0**: Session never expires (token remains valid indefinitely)

The user's `lastEntryTime` is updated on each successful request to track activity.

### Session Requirements

For a token to be valid:

- Token signature must be valid
- Username in token must match an active user
- User status must be `ACTIVE`
- Session must not have expired (based on `lastEntryTime` + expiration setting)

## Logout

### Endpoint

```
POST /api/logout/{userId}
```

Invalidate the user's session and log them out.

### Path Parameters

<ParamField path="userId" type="integer" required>
  ID of the user to log out
</ParamField>

### Example Request

<CodeGroup>
```bash cURL
curl -X POST \
  https://your-instance.opencbs.cloud/api/logout/123 \
  -H 'Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...' \
  -H 'Content-Type: application/json'
```

```javascript JavaScript
await fetch(`https://your-instance.opencbs.cloud/api/logout/${userId}`, {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  }
});
```

```python Python
requests.post(
    f'https://your-instance.opencbs.cloud/api/logout/{user_id}',
    headers={'Authorization': f'Bearer {token}'}
)
```
</CodeGroup>

## Password Management

### Update Password

```
PUT /api/login/update-password
```

Change a user's password. This endpoint is publicly accessible.

#### Request Body

<ParamField body="userId" type="integer" required>
  ID of the user whose password to update
</ParamField>

<ParamField body="password" type="string" required>
  New password (must meet validation requirements)
</ParamField>

#### Example Request

<CodeGroup>
```bash cURL
curl -X PUT \
  https://your-instance.opencbs.cloud/api/login/update-password \
  -H 'Content-Type: application/json' \
  -d '{
    "userId": 123,
    "password": "newSecurePassword123!"
  }'
```

```javascript JavaScript
await fetch('https://your-instance.opencbs.cloud/api/login/update-password', {
  method: 'PUT',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    userId: 123,
    password: 'newSecurePassword123!'
  })
});
```
</CodeGroup>

#### Response

```
Password has been successfully changed
```

## Security Best Practices

<Note>
Follow these security guidelines when working with authentication:
</Note>

### Token Storage

- **Never** store tokens in localStorage (vulnerable to XSS)
- Use httpOnly cookies when possible
- Store in memory for single-page applications
- Use secure storage mechanisms on mobile devices

### Token Transmission

- Always use HTTPS in production
- Never log tokens or include them in URLs
- Don't send tokens in query parameters

### Session Security

- Implement logout on user action
- Clear tokens when user logs out
- Handle token expiration gracefully
- Re-authenticate users for sensitive operations

### Error Handling

```javascript
async function makeAuthenticatedRequest(url, token) {
  const response = await fetch(url, {
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    }
  });

  if (response.status === 401) {
    // Token invalid or expired - redirect to login
    window.location.href = '/login';
    return;
  }

  return response.json();
}
```

## Common Issues

### 401 Unauthorized

**Possible causes:**
- Token not included in request
- Token malformed or corrupted
- Invalid credentials during login
- User account is not active
- Session has expired

**Solution:** Verify token is correctly formatted and included in the `Authorization` header with `Bearer` prefix.

### Session Expired

**Cause:** Session exceeded the configured `EXPIRATION_SESSION_TIME_IN_MINUTES` without activity.

**Solution:** Re-authenticate by calling `/api/login` again.

### User Not Found

**Cause:** Username in token doesn't match any active user.

**Solution:** Verify the user account exists and is active.
