## Overview

The Groups API allows you to create, retrieve, update, and manage group profiles. Groups represent collections of people (e.g., solidarity groups, community groups) and are commonly used for group lending.

## Get Group by ID

<CodeGroup>
```bash GET /api/profiles/groups/{id}
curl -X GET "https://api.opencbs.com/api/profiles/groups/123" \
  -H "Authorization: Bearer YOUR_TOKEN"
```
</CodeGroup>

Retrieve detailed information about a specific group.

<ParamField path="id" type="long" required>
  The unique identifier of the group
</ParamField>

### Response

<ResponseField name="id" type="long">
  Group identifier
</ResponseField>

<ResponseField name="name" type="string">
  Group name
</ResponseField>

<ResponseField name="status" type="string">
  Current status: `LIVE`, `PENDING`, `DEAD`
</ResponseField>

<ResponseField name="customFieldSections" type="array">
  Custom field sections with dynamic group data
  <Expandable title="Custom Field Section">
    <ResponseField name="caption" type="string">
      Section title
    </ResponseField>
    <ResponseField name="values" type="array">
      Array of field values in this section
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="groupsMembers" type="array">
  List of people who are members of this group
  <Expandable title="Member Object">
    <ResponseField name="id" type="long">
      Member profile ID
    </ResponseField>
    <ResponseField name="name" type="string">
      Member name
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="branch" type="object">
  Branch information
  <Expandable title="Branch Object">
    <ResponseField name="id" type="long">
      Branch identifier
    </ResponseField>
    <ResponseField name="name" type="string">
      Branch name
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="attachments" type="array">
  Document attachments for the group
</ResponseField>

<ResponseField name="isReadOnly" type="boolean">
  Whether the group can be edited
</ResponseField>

### Error Responses

<ResponseField name="404" type="error">
  ```json
  {
    "message": "Group not found (ID=123)."
  }
  ```
</ResponseField>

## Create Group

<CodeGroup>
```bash POST /api/profiles/groups
curl -X POST "https://api.opencbs.com/api/profiles/groups" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fieldValues": [
      {
        "fieldId": 1,
        "code": "group_name",
        "value": "Community Savings Group"
      },
      {
        "fieldId": 2,
        "code": "formation_date",
        "value": "2024-01-15"
      },
      {
        "fieldId": 3,
        "code": "description",
        "value": "Village savings and loan association"
      }
    ]
  }'
```
</CodeGroup>

Create a new group profile. This creates a maker-checker request that requires approval.

### Request Body

<ParamField body="fieldValues" type="array" required>
  Array of custom field values defining the group
  <Expandable title="Field Value Object">
    <ParamField body="fieldId" type="long">
      The custom field identifier
    </ParamField>
    <ParamField body="code" type="string">
      Field code (e.g., "group_name", "formation_date")
    </ParamField>
    <ParamField body="value" type="string">
      The value for this field
    </ParamField>
  </Expandable>
</ParamField>

### Response

<ResponseField name="id" type="long">
  The maker-checker request ID. This request must be approved by a checker before the group is created.
</ResponseField>

### Permissions

Requires `MAKER_FOR_GROUP` permission with `ModuleType.MAKER_CHECKER`.

## Update Group

<CodeGroup>
```bash PUT /api/profiles/groups/{id}
curl -X PUT "https://api.opencbs.com/api/profiles/groups/123" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fieldValues": [
      {
        "fieldId": 1,
        "code": "group_name",
        "value": "Updated Group Name"
      }
    ]
  }'
```
</CodeGroup>

Update an existing group. Creates a maker-checker request for the update.

<ParamField path="id" type="long" required>
  Group identifier
</ParamField>

### Request Body

Same as Create Group request body. The ID is automatically set from the path parameter.

### Response

<ResponseField name="id" type="long">
  The maker-checker request ID for this update
</ResponseField>

### Permissions

Requires `MAKER_FOR_GROUP` permission.

## Add Member to Group

<CodeGroup>
```bash POST /api/profiles/groups/{id}/members/add/{memberId}
curl -X POST "https://api.opencbs.com/api/profiles/groups/123/members/add/456" \
  -H "Authorization: Bearer YOUR_TOKEN"
```
</CodeGroup>

Add a person as a member of the group.

<ParamField path="id" type="long" required>
  Group identifier
</ParamField>

<ParamField path="memberId" type="long" required>
  Profile ID of the person to add as a member
</ParamField>

### Response

Returns the updated group detail object including the new member in the `groupsMembers` array.

<ResponseField name="id" type="long">
  Group identifier
</ResponseField>

<ResponseField name="name" type="string">
  Group name
</ResponseField>

<ResponseField name="groupsMembers" type="array">
  Updated list of members including the newly added person
</ResponseField>

### Error Responses

<ResponseField name="400" type="error">
  Validation error - member may already be in the group or validation rules failed
  ```json
  {
    "message": "Member validation failed"
  }
  ```
</ResponseField>

<ResponseField name="404" type="error">
  Group or member profile not found
</ResponseField>

</ParamField>

## Maker-Checker Workflow

Group creation and updates use a maker-checker workflow:

1. **Maker** creates a request via POST or PUT endpoints
2. Request is submitted with status `PENDING`
3. **Checker** reviews and approves/rejects the request
4. Upon approval, the group is created or updated

The POST and PUT endpoints return a `RequestDto` with the request ID, not the final group ID.

## Common Error Codes

| Status Code | Description |
|-------------|-------------|
| 400 | Bad Request - Invalid input, validation failure, or business rule violation |
| 401 | Unauthorized - Missing or invalid authentication token |
| 403 | Forbidden - User lacks required permissions |
| 404 | Not Found - Group or member profile does not exist |
| 500 | Internal Server Error - Unexpected server error |

## Best Practices

- Always validate member IDs before adding them to groups
- Use the lookup endpoint to search for available members
- Handle maker-checker request IDs appropriately - they are not group IDs
- Check for active loans or transactions before removing members
- Implement proper error handling for validation failures
