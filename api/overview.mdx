## Base URL

All API endpoints are prefixed with `/api`:

```
https://your-instance.opencbs.cloud/api
```

## Request Format

The OpenCBS API uses standard REST conventions:

- **GET** - Retrieve resources
- **POST** - Create new resources
- **PUT** - Update existing resources
- **DELETE** - Remove resources

### Content Type

All requests that send data must include the `Content-Type` header:

```
Content-Type: application/json
```

## Response Format

### Successful Responses

Most successful API responses are wrapped in a standard `ApiResponse` object:

```json
{
  "data": {
    // Response payload
  }
}
```

For simple operations, the response may be a plain string or object without the wrapper.

### Response Codes

| Status Code | Description |
|------------|-------------|
| 200 | Success - Request completed successfully |
| 201 | Created - Resource created successfully |
| 400 | Bad Request - Invalid input or validation error |
| 401 | Unauthorized - Missing or invalid authentication |
| 404 | Not Found - Resource does not exist |
| 500 | Internal Server Error - Server-side error |

## Error Handling

When an error occurs, the API returns an `ErrorResponse` with the following structure:

<ResponseField name="httpStatus" type="integer" required>
  HTTP status code (e.g., 400, 401, 404, 500)
</ResponseField>

<ResponseField name="errorCode" type="string" required>
  Machine-readable error code for programmatic handling
</ResponseField>

<ResponseField name="message" type="string" required>
  Human-readable error description
</ResponseField>

### Error Response Example

```json
{
  "httpStatus": 401,
  "errorCode": "invalid_credentials",
  "message": "Invalid username or password."
}
```

## Authentication

All API requests (except public endpoints) require authentication using Bearer token authentication. See the [Authentication](/api/authentication) guide for details.

### Protected vs Public Endpoints

Most endpoints require authentication. The following endpoints are publicly accessible:

- `POST /api/login` - User login
- `PUT /api/login/update-password` - Update password
- `POST /api/login/password-reset` - Reset password
- `GET /api/info` - System information
- `GET /api/system-settings` - System settings
- `GET /api/utils/**` - Utility endpoints
- `GET /api/profiles/*/attachments/*` - Public attachments

## Rate Limiting

<Note>
The current implementation does not enforce rate limiting at the API level. However, session-based access control is managed through configurable session expiration times.
</Note>

Session timeout can be configured via the `EXPIRATION_SESSION_TIME_IN_MINUTES` system setting. When set to `0`, sessions never expire.

## Common Patterns

### Pagination

Endpoints that return lists typically support pagination using Spring's `Pageable` interface:

```bash
GET /api/currencies/lookup?page=0&size=20&search=USD
```

<ParamField query="page" type="integer" default="0">
  Page number (zero-indexed)
</ParamField>

<ParamField query="size" type="integer" default="20">
  Number of items per page
</ParamField>

<ParamField query="search" type="string">
  Optional search filter
</ParamField>

### Pagination Response

```json
{
  "content": [...],
  "totalElements": 100,
  "totalPages": 5,
  "size": 20,
  "number": 0
}
```

### Lookup Endpoints

Many resources provide `/lookup` endpoints for searching and pagination:

```bash
GET /api/currencies/lookup?search=USD&page=0&size=10
```

### Standard CRUD Operations

Most resources follow standard REST patterns:

- `GET /api/{resource}` - List all
- `GET /api/{resource}/{id}` - Get by ID
- `POST /api/{resource}` - Create new
- `PUT /api/{resource}/{id}` - Update existing
- `DELETE /api/{resource}/{id}` - Delete

## CORS and Security

The API uses stateless JWT-based authentication with Spring Security. Key security features:

- CSRF protection is disabled (stateless tokens used instead)
- Session policy: `STATELESS`
- OPTIONS requests are permitted for CORS preflight

## Example Request

<CodeGroup>
```bash cURL
curl -X GET \
  https://your-instance.opencbs.cloud/api/currencies \
  -H 'Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...' \
  -H 'Content-Type: application/json'
```

```javascript JavaScript
const response = await fetch('https://your-instance.opencbs.cloud/api/currencies', {
  method: 'GET',
  headers: {
    'Authorization': 'Bearer eyJhbGciOiJIUzUxMiJ9...',
    'Content-Type': 'application/json'
  }
});

const data = await response.json();
```

```python Python
import requests

headers = {
    'Authorization': 'Bearer eyJhbGciOiJIUzUxMiJ9...',
    'Content-Type': 'application/json'
}

response = requests.get(
    'https://your-instance.opencbs.cloud/api/currencies',
    headers=headers
)

data = response.json()
```
</CodeGroup>
